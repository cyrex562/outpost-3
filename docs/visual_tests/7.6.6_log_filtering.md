### Manual Visual Test Procedure

When running the client with debug overlay enabled (`F12` or debug mode):

#### 1. Log Filter UI Visibility

- [ ] Debug overlay shows a "Log Filters" section
- [ ] Section displays 4 checkboxes: Debug, Info, Warn, Error
- [ ] All checkboxes are initially checked (all levels shown)
- [ ] Category filter text input is visible and empty

#### 2. Individual Level Filters

- [ ] Uncheck "Debug" → Debug-level logs disappear from panel
- [ ] Uncheck "Info" → Info-level logs disappear from panel
- [ ] Uncheck "Warn" → Warn-level logs disappear from panel
- [ ] Uncheck "Error" → Error-level logs disappear from panel
- [ ] Re-check any level → Logs at that level reappear

#### 3. Category Filtering

- [ ] Type "building" in category filter → Only logs with "building" in category show
- [ ] Type "resource:production" → Only logs matching both terms show
- [ ] Clear the text → All category-matching logs return
- [ ] Partial match works (e.g., "prod" matches "production")

#### 4. Combined Filtering (Level + Category)

- [ ] Check Debug + Warn, filter by "building"
  - [ ] Only DEBUG and WARN level logs with "building" appear
- [ ] Check only Info, filter by "resource"
  - [ ] Only INFO level logs with "resource" appear
- [ ] Category filter with all levels disabled
  - [ ] No logs appear (correct behavior)

#### 5. Performance Check (from test_debug_overlay_performance)

- [ ] When multiple filters are active, overlay remains smooth
- [ ] No visible frame rate drops when updating filters
- [ ] Switching filters is responsive (< 16ms per frame)

### Implementation Notes

- Filter state is stored in `DebugLogFilter` resource with `Clone` derive
- Default shows all levels (all bool flags true, empty category string)
- Category filtering uses substring matching for flexibility
- UI integration happens in the egui debug overlay system
- Filters are applied when rendering log entries to the debug panel
